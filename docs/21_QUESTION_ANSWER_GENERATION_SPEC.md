## 2. CSV 행 구조와 문제 생성 (`generateQuestion`)

| 열 | 의미 | 예 |
|---|---|---|
| Level / SubLevel | 난이도 대분류 / 세부 단계 | 1 / 1 |
| LevelTitle / SubLevelTitle | 표시명 | 덧뺄셈 / 한자리 |
| QuestionTemplate | 지문 템플릿 (`{A}`, `{A*B}`, `{sup(B)}` 등) | `{A} + {B} = ?` |
| AnswerEval | 정답 수식 | `A+B` |
| WrongEval | 오답 수식 | `A+B+pick(-2,-1,1,2)` |
| VarA~VarD | 변수 생성식 (뒤 변수가 앞 변수 참조 가능) | `rand(1,9)` |
| ShapeCode | 도형/그림 코드 (있으면 도형 문항) | 공란 |

생성 순서 (`QuestionEvaluator.ts:179~230`):
1. `A → B(A 참조) → C(A,B) → D(A,B,C)` 순차 `safeEval` (화이트리스트 함수만 허용: `rand`, `pick`, `gcd`, `factorial`, `sup`, `repeatAdd`, `repeatMul` 등).
2. 템플릿 `{...}` 치환으로 `questionText` 생성.
3. `AnswerEval` → `correctAnswer`, `WrongEval` → `wrongAnswer`.
4. 오답이 무효이거나 정답과 같으면 `generateFallbackWrong()`으로 보정.
5. 정답 위치는 `Math.random() < 0.5`로 좌/우 결정 → `choices: [a, b]`.
6. 난수원: `Math.random` (seed 없음, 재현 불가).

정답 타입:
- **숫자형**: `14`, `0.5` 등
- **문자열형**: 비교기호(`>`, `<`, `=`), 분수(`5/14`), 거듭제곱 표기(`2³ × 9`), 2진수(`1000₍₂₎`), 백분율(`34%`), 기호(`↘️`) 등

## 5. Boss Assault 오답(보기 쌍) 생성 규칙 (`AssaultAnswerPairFactory.ts`)

정답 1개에 대해 `pairCount(=4)`개의 서로 다른 오답을 seed RNG로 선택한다.

**정수 정답** 후보군 (우선순위 순):
1. 기본 오프셋 `±1, ±2, ±10` (DEC-A5)
2. 자릿수 전위 (12 → 21)
3. 1의 자리 10의 보수, 1의 자리 +5 변형
4. 추가 오프셋 `±3~±9, ±11, ±12, ±15, ±20, ±30`
5. 부족 시 `±13 ~ ±100` 동적 확장

**소수 정답** 후보군: 소수 자릿수 step 기준 `±1, ±2, ±5, ±10 step`, `±1`, `±2`, 부족 시 `±3~50 step`.

공통 필터:
- 정답과 수치적으로 같은 값 제외 (`|cand − correct| < 1e-9`)
- 정답 ≥ 0 이면 음수 오답 제외
- 중복 값 제외
- 후보 부족 시 `AssaultAnswerPairError`

- 현재 Level/SubLevel(덧셈·뺄셈·곱셈 등 연산 축) 구조와 별개로, **유형 축 스테이지**(10 만들기, 분수 비교, 소수 곱하기 등)를 제공한다.

### 12.3 해결: 7~9단계 하프타임 판정

- 음악은 165~195 BPM 그대로 재생하고, **게임 판정 박자만 절반**(82~98)으로 센다.
- 쌍당 4박 규칙(DOC-19)은 유지 — 박자를 세는 기준만 바뀐다.

| 단계 | 음악 BPM | 판정 박자 | 선택 시간 | 판단 시간 |
|---|---|---|---|---|
| 7 | 170 | 85 | 2.82초 | 1.82초 |
| 8 | 180 | 90 | 2.67초 | 1.67초 |
| 9 | 195 | 97.5 | 2.46초 | 1.46초 |

**동작 부담**: 4박 기준 160 BPM에서는 스쿼트 회피가 2박 = 0.75초로 짧다. 하프타임(판정 80~98)이면 회피 1.2~1.5초로 1단계 수준이 된다. 걸음 박자는 §12.6 참조.

**구현 요구**: 곡 메타데이터에 판정 박자 `gameplayBpm` 추가 (예: 음악 190 / 판정 95). 세션의 `bpm` 옵션은 기존 지원 — 해당 값으로 `gameplayBpm` 전달.

| 항목 | 문제 |

### 12.5 하프타임 곡 제작 가이드 (7~9단계)

1. **판정 박자를 분명하게**: 킥·스네어를 판정 박자(예: 95)에 맞춘다. 190 BPM 마디 기준 스네어를 3박에 두면 하프타임 느낌 → 이 박이 펀치 타이밍.
2. **빠른 느낌은 나머지 악기로**: 하이햇, 브레이크비트, 현악 속주는 190 BPM 그대로 촘촘하게 연주해 긴장감 유지.
3. **곡 정보에 두 값 함께 표시**: `음악 190 / 판정 95` → 게임 반영 시 `gameplayBpm`.

### 12.6 단계별 판정 박자 흐름

| 단계 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| 음악 BPM | 110 | 120 | 130 | 140 | 150 | 160 | 170 | 180 | 190 |
| 판정 박자 | 110 | 120 | 130 | 140 | 150 | 160 | **85** | **90** | **95** |
| 판정 방식 | 4박 | 4박 | 4박 | 4박 | 4박 | 4박 (확정) | 하프타임 (확정) | 하프타임 (확정) | 하프타임 (확정) |
| 걸음 (분당) | 110 | 120 | 130 | 140 | 150 | 160 | 170 | 180 | 190 |
| 난이도 축 | 반응 속도 | ← | ← | ← | ← | ← | **사고력** | → | → |

**걸음 박자 규칙 (확정)**: **음악 한 박에 한 걸음**.
- 7~9단계(하프타임): 판정 박자의 **반 박에 한 걸음** → 분당 170~190걸음 (달리기 리듬).
- 1~6단계(4박): 판정 박자 = 음악 박자이므로 **한 박에 한 걸음** → 분당 110~160걸음 (가벼운 조깅~조깅).
- 주의: 1~6단계에도 반 박에 한 걸음을 적용하면 분당 220~320걸음이 되어 수행 불가. 반 박 규칙은 하프타임 단계에만 적용한다.
- 달리기 판정(RunDetector)은 미완성 — 해당 구현 카드에서 이 규칙(걸음 간격 = 60 ÷ 음악 BPM 초)을 기준값으로 사용한다.

- 1~6단계: 박자가 빨라지며 쉬운 문제를 빠르게 푼다.
- 7~9단계: 판정 박자가 느려지는 대신 어려운 문제(제곱수, 루트, 역수, 11의 배수 ②)를 푼다.

## 13. 답안 보기 난이도 A1~A3 (To-Be, Boss Assault 전용)

### 13.1 목적과 결정 사항 (2026-11-09)

현재 오답은 정답 **숫자만** 보고 오프셋(±1, ±2, ±10…, §5)을 균등 추첨한다. 문제의 연산 구조를 모르기 때문에 `78 × 100` → `7800 / 7700`처럼 오개념과 무관하거나, `7800 / 7801`처럼 끝자리만 보고 고르는 보기가 나온다. 본 절은 **"플레이어가 어떤 계산을 해야 정답을 가려낼 수 있는가"**로 보기 난이도를 정의한다.

| # | 결정 | 내용 |
|---|---|---|
| D1 | A3 표시 방식 | **공격(보기 쌍)마다 보조 문구** `pairPromptText` 표시 (휴식 박 재도입 없음, `ASSAULT_LOOP_REST_BEATS = 0` 유지) |
| D2 | A3 배정 | **각 챕터의 가장 마지막 SubLevel** |
| D3 | 진행 순서 | GitHub 이슈 카드 등록 우선, 구현은 카드별 개별 승인 |
| D4 | 적용 범위 | **boss_assault 전용**. 일반 모드 2지선다(`generateQuestion` 오답 1개)는 변경하지 않는다 |

명칭: §11의 **T1~T4는 문제 판단 시간 등급**이다. 본 절의 **A1~A3는 보기(Answer) 난이도**이며 두 축은 독립이다.

### 13.2 등급 정의

| 등급 | 이름 | 플레이어 행동 | 오답 성격 | 예 |
|---|---|---|---|---|
| **A1 하** | 어림 | 대충 계산해도 고를 수 있다 | 크기가 크게 다른 값(정답 대비 ±50% 이상, 자릿수 2개 이상 차이), 문제에 나온 숫자 그대로 | `7 + 5` → 12 / 30, `78 × 100` → 7800 / 78 |
| **A2 중** | 정밀 | 끝까지 정확히 계산해야 고를 수 있다 | 연산 오개념을 다시 계산한 값 (§13.4) | `78 × 100` → 7800 / 780, 78000 · `47 + 38` → 85 / 75 |
| **A3 상** | 연쇄 | 계산한 뒤 쌍마다 규칙을 더 적용해야 고를 수 있다 | 쌍별 정답이 바뀌고, 규칙 누락·중복 적용 값이 오답 | `7 × 8`: 56 → +1 → 57 → +1 → 58 → +1 → 59 |

- 기준은 **정답과의 거리가 아니라 "계산 없이 고를 수 있는가"**이다. 같은 자릿값 오답이라도 ×10 차이(780)는 A2, ×100 이상 차이(78)는 A1로 전략마다 등급을 지정한다.

### 13.3 등급 배정 (D2)

| 대상 | 등급 |
|---|---|
| 튜토리얼 (`AssaultTutorialController`) | A1 |
| 각 챕터 SubLevel 1 | A1 |
| 각 챕터 중간 SubLevel | A2 |
| 각 챕터 **마지막 SubLevel** | A3 |

현행 Assault 허용 범위(`allowedLevels: [1,2,3,4]`) 기준 마지막 SubLevel:

| 챕터 | 마지막 SubLevel | 내용 | A3 주의점 |
|---|---|---|---|
| Ch.1 덧뺄셈 | 1-7 빈칸역산 | `[ ? ] + B = C` | 정답 + 규칙 그대로 적용 가능 |
| Ch.2 곱나눗셈 | 2-5 복합곱 | `A × B` (**CSV 2행뿐**, Q-DATA-1) | 반복도 높음 → Q-DATA-1 보강 권장 |
| Ch.3 분수 | 3-5 곱나눗셈 | `1/(A×B)`, 역수 등 | 규칙은 **분모 유지, 분자 +1** |
| Ch.4 소수 | 4-5 응용문제 | `toFixed` 소수 | 규칙은 **최하위 자리 +1 step** (예 +0.1) |

- 마지막 SubLevel 번호는 하드코딩하지 않고 `QuestionBank`의 SubLevel 목록에서 최댓값으로 산출한다. Ch.5 이후 `allowedLevels` 확장 시 자동 적용.
- 배정 표는 `config/answer-tier.config.ts`에서 관리하며, 챕터별 override를 허용한다.

### 13.4 A2 오개념 전략

| 전략 | 적용 태그 | 예 (정답 → 오답) | 기본 등급 |
|---|---|---|---|
| 자릿값 이동 ×10ᵏ / ÷10ᵏ | `place_value` | 78×100: 780, 78000 | k=1: A2, k≥2: A1 |
| 받아올림·받아내림 누락 | `carry`, `borrow` | 47+38=85 → 75 / 52−27=25 → 35 | A2 |
| 피연산자 ±1 재계산 | `mul`, `div` | 7×8=56 → 63, 48 | A2 |
| 연산자 혼동 | 사칙 | 6×3=18 → 9 | A1~A2 (크기 차이로 판정) |
| 연산 순서 오류 | `order_of_ops` | 2+3×4=14 → 20 | A2 |
| 소수점 위치 오류 | `decimal` | 0.3×0.2=0.06 → 0.6, 0.006 | A2 |
| 분수 오개념 | `fraction` | 1/2+1/3=5/6 → 2/5 | A2 |
| 경계값 착오 (off-by-one) | `range` | 1~n 합 → 1~(n−1) 합 | A2 |
| CSV `WrongEval` 전 분기 | 전 행 | `pick(-10,10,20)` 3분기 모두 후보화 | 크기 차이로 판정 |
| 끝자리만 다른 근접값 (±1) | 폴백 | 7800 → 7801 | 오개념 아님 → **최후 폴백** |

- **수식 분석은 `AnswerEval` 문자열 + 실제 대입된 변수 값**으로 판정한다 (CSV 68행 `A*B`, `VarB = pick(10,100,1000)`은 값으로만 `place_value` 판정 가능).
- 공통 필터 유지: 수치 동치 제외(`Rational.equals`), 비음수 정답이면 음수 제외, 라벨 6자 이내(`maxLabelChars`), 중복 제외. 6자 초과 시 다음 전략으로 폴백.
- 4쌍은 **서로 다른 전략**을 우선 사용한다. 난수는 `utils/seededRng.ts` `createSeededRng`만 사용한다 (`AssaultAnswerPairFactory.ts:74`의 비공개 Mulberry32 신규 사용 금지).

### 13.5 A3 연쇄 규칙 (D1)

```text
러닝 8박: 문제 "7 × 8 = ?" + 규칙 공지 "답할 때마다 +1" (TTS 1회)
쌍1 보조 문구 "7 × 8 = ?"     정답 56   오답 예 57(미리 적용) / 63(A2)
쌍2 보조 문구 "앞 답 + 1"     정답 57   오답 예 56(규칙 누락) / 58(중복 적용)
쌍3 보조 문구 "앞 답 + 1"     정답 58   오답 예 57 / 59
쌍4 보조 문구 "앞 답 + 1"     정답 59   오답 예 58 / 60
```

1. **기준은 실제 정답 연쇄**이다. 플레이어가 고른 값이 아니다. 한 번 틀려도 다음 쌍이 연쇄로 망가지지 않는다 (DOC-18 §4.4 오답 전파 방지와 동일 원칙).
2. 보조 문구는 기존 `pairPromptText` 필드를 사용한다 (`types/assault.ts:189/242/312`, `AssaultRoundPresentationBuilder.ts:200`). **현재 Render(`AssaultSceneRenderer`/`AssaultPairPainter`)에 표시 경로가 없음** → 별도 Render 카드.
3. 규칙 계산은 DOC-18 D계열 `ProgressionGenerator`(`D1_skip_count`)와 **공통 순수 함수로 추출하여 공유**한다 (DRY). 루프 모드는 `challenge` 공급을 거부(`AssaultLoopRoundAssembler.ts:181`)하므로 A3는 numeric_repeat 경로 안에서 처리한다.
4. 규칙 종류 (config): 정수 `+1`(기본), 분수 `분자 +1`, 소수 `최하위 step +1`. 결과가 음수·6자 초과·분모 0이면 시드 기반 대체 규칙.
5. 쌍별 정답이 달라도 판정기는 `correctSide`만 비교(`AssaultPairJudge`)하므로 **판정 로직 무수정**.
6. A3 오답 우선순위: 규칙 누락 값(직전 정답) → 중복 적용 값 → A2 오개념.
7. 판단 시간: §11.1 쌍당 실제 판단 약 0.8~1.2초. 쌍2부터는 "직전 정답 + 1"만 계산하므로 T1~T2 수준이다. 단 쌍1은 원 문제 계산이 필요하므로 러닝 8박 중 미리 계산하도록 문제를 먼저 노출한다(현행 유지).
