## 1. 개요 및 논의 배경

### 1.1 현행 게임 루프의 문제의식
- **현행 루프 구조**: `러닝 문제 출제(8슬롯) → 답안 선택(좌/우 1회) → 정답 페이즈(별모으기 7개) / 오답 페이즈(장판 회피) → 10회 반복 후 보스 결전(피버 모드)`
- **인지된 한계**:
  1. **템포 저하 (루즈함)**: 문제를 보고 답을 고른 뒤, 정답/오답 결과에 따라 게임 흐름이 완전히 분기되며 동작 템포가 늘어짐.
  2. **타격감 부족**: 문제를 풀고 나서 좌우로 팔을 한 번 뻗는 방식에 머물러 연속 타격(리듬 펀치)의 시원한 쾌감이 부족함.
  3. **단절된 페이즈 전이**: 정답 페이즈와 오답 페이즈가 별도로 나뉘어 게임 전체의 연속적인 몰입감(Flow)이 끊어짐.

### 2.1 단계 1: 최초 문제 제기 및 아이디어 제안 (사용자)
- **사용자 제안 내용**:
  > "게임 방식을 이렇게 하는건 어때?? 지금은 러닝문제-답펀치-정답 펀치펀치/오답점프-피버모드(보스대결) 인데 이 루즈함을...<br>
  > 정답을 양옆에 띄우는게 아니라 계속해서 다른 답들이 2개씩 날아오고 나는 그중에서 답을 골라 펀치하는거지. 대략 8박동안 4번 정도의 펀치?<br>
  > 그럼 펀치도 더 많아지고 펀치하는 시원함에 정답,오답 페이즈가 다를 필요가 없고, 최종적으로 맞힌 답의 수를 집계하면 순위도 괜찮을거 같고.<br>
  > 추후 어려운 문제에서는 똑같은 답이 아니라 12가 되는 수 라는 문제로 6+6, 7+5, 14-2 같은 문제형식의 답을 고를수도 있을거 같은데?<br>
  > 우리 게임에 적용 가능한지 여부와 긍정적 비판적인 의견 부탁해."

### 2.2 단계 2: 1차 기술 검토 및 다각적 분석 (에이전트)
- **적용 가능 여부**: **충분히 가능** (QuestionBank, Motion/Input, StateMachine 계층 분리 덕분에 코어 구조 보존 하에 확장 가능)
- **긍정적 측면**:
  1. *리듬 펀치 액션성 극대화*: Beat Saber / Fitness Boxing 스타일의 연속 타격감 및 끊김 없는 플로우 확보.
  2. *수학적 사고력 훈련*: 단순 연산($7+5=?$)을 넘어 수의 분해·합성 및 역연산($12$ 만들기) 훈련으로 교육적 가치 상승.
  3. *상체 운동량 증가*: 문제당 펀치 횟수 증가로 상체 유산소 피트니스 소모량 증가.
  4. *스코어링 정밀화*: 맞힌 타겟 수, 콤보, 리듬 정확도를 집계하는 랭킹 체계 도입 용이.
- **비판적/우려 측면 (주의 과제)**:
  1. *인지 과부하 (Cognitive Overload)*: 1~2초 내에 두 수식을 암산 비교하고 신체 조준까지 마치는 것은 초등학생에게 과도한 패닉 유발 가능.
  2. *웹캠 모션 인식(MediaPipe) 지연 및 연타 씹힘*: 30~50ms 레이턴시 환경에서 팔을 미처 회수하지 못한 상태의 판정 오작동 위험.
  3. *하체 운동 실종*: 펀치에만 치중할 경우 달리기, 스쿼트, 점프 등 링피트 스타일 전신 피트니스 정체성 훼손.

### 2.3 단계 3: 복합 피트니스 및 난이도별 템포 1차 구체화 (에이전트)
- **핵심 원칙**: "수학 판단은 펀치 구간에 집중하고, 전신 운동은 짧은 연결 구간에 배치하되 음악과 진행은 끊지 않는다."
- **16박 기본 루프안 제안**:
  - `준비 4박 (문제 읽기 + 가볍게 달리기)` → `답 펀치 8박 (날아오는 답 4회 타격)` → `전신 운동 4박 (스쿼트/스텝)`
- **운동 역할 분담**:
  - 제자리 달리기: 이동 및 문제 인지
  - 좌우 펀치: 수학 정답 선택
  - 스쿼트/점프: 상단/하단 장애물 회피

### 2.4 단계 4: 컨셉의 결정적 대전환 (사용자 피드백)
- **사용자 피드백 내용**:
  > "문제가 4박인건 너무 짧아 문제에 대해 생각할 시간이 필요해 8박 정도는 필요해.<br>
  > 문제는 전면의 보스가 던지는 데 문제를 쾅 던지고 양손 공격으로 답을 던지는 거지 - 정답펀치와 스쿼트동작 번갈아서.<br>
  > 유저가 정답시에는 보스의 공격이 무효화되고 오답시에는 그대로 날아와 유저에게 펑 유저의 hp가 깎이고.<br>
  > 보스앞에 다다랐을때 보스와 펀치+피하기+점프공격+등등으로 대결. 이런흐름 어때?"

- **의사결정 및 정립된 핵심 게임플레이**:
  1. **생각 시간 8박 보장**: 4박은 암산에 절대적으로 부족함. 문제 등장 연출이 끝난 뒤 온전히 문제를 읽고 생각할 수 있는 **최소 8박(BPM 100 기준 4.8초)**을 필수로 보장한다.
  2. **보스의 문제 투척 연출**: 보스가 문제를 전면에 쾅! 내리꽂으며 라운드가 시작됨.
  3. **양손 답 공격 ↔ 스쿼트 회피 교대**: 보스 양손에서 답 2개가 탄환으로 날아오며(정답 펀치), 이어서 보스의 가로 휘두르기 공격(스쿼트 회피)이 번갈아 전개됨.
  4. **인과율의 명확화 (정답 무효화 vs 오답 피격)**:
     - 정답 탄환을 펀치하면 에너지 연결이 붕괴되며 **공격 쌍 전체가 무효화**됨.
     - 오답 탄환을 치거나 놓치면 공격이 그대로 날아와 **도착 시점에 플레이어에게 피격(HP 감소)** 발생.
     - 별도의 정답/오답 전용 화면으로 분기하지 않고 단일 타임라인에서 즉각적인 결과 처리.
  5. **보스 접근 진행도**: 라운드를 거듭할수록 배경과 보스 크기가 변하며 점진적으로 보스에게 접근.
  6. **근접 결전 (Finale)**: 보스 앞에 도달하면 학습한 펀치, 스쿼트 회피, 점프 공격을 조합한 박진감 넘치는 대결 진행.

### 2.5 단계 5: 시스템 변경 범위 목록화 및 아키텍처 충돌 방지
- **기존 코드 정밀 조사 결과**:
  - `BeatRunCoordinator`는 1문제 1선택 및 정답/오답 분기에 강하게 결합되어 있음.
  - `BeatRoundResolver`는 라운드당 단일 상태(`correct/wrong/timeout`)만을 정산하도록 설계됨.
  - `BattleState`는 HP/마나의 권위를 가지나 다중 공격 ID 중복 방지 로직이 없음.
- **수정/변경/추가 체계화**:
  - **수정 (Modify)**: 문제 생각 시간 분리(8박 보장), 문제 상시 표시, 펀치 re-arm(손 회수 후 재타격), 스쿼트 안전 판정, 밸런스 수치 조정.
  - **변경 (Replace)**: 단일 선택 → 반복 답 펀치, 정답/오답 화면 분기 제거, 선택 후 2박 쉼표 제거, 오답 시 도착 시점 단일 피해, 다중 결과 라운드 정산.
  - **추가 (Add)**: 보스 투척 연출, 양손 답 공격 묶음(pairId), 교대 타임라인, 무효화/피격 연출, 접근 진행도, 근접 결전 패턴.
- **무충돌 격리 원칙 확립**:
  - 기존 `legacy` 모드와 신규 `boss_assault` 모드를 세션 단위로 완전히 격리.
  - 신규 모드 실행 중에는 레거시 컨트롤러, 별모으기, 피버/포격 시스템의 실행 및 피해/보상 호출을 100% 차단.

### 2.6 단계 6: 데이터와 로직의 분리 원칙 확립 (사용자 강조)
- **사용자 지침**:
  > "진행해줘 - 데이터와 로직을 분리해서 설계해야 하는 것을 잊지마"
- **설계 문서(DOC-14 v0.2) 반영 사항**:
  1. **물리적 레이어 분리**:
     - *타입 계약 (`src/types/assault*.ts`)*: 불변 스키마 및 상태 인터페이스 정의.
     - *설정 (`config/assault*.config.ts`)*: 타이밍, 판정창, 피해량 등 튜닝 수치 관리.
     - *공격 콘텐츠 (`src/data/assault/`)*: 공격 종류, 순서, 박자 배치를 선언형 데이터로 분리.
     - *순수 로직 (`src/game/assault/`)*: 데이터 검증(Validator), 불변 계획 컴파일(Planner), 순수 판정(Judge).
     - *자원 정산*: 중복 방지 기반의 단일 피해/보상 적용.
     - *표시 계층 (`src/render/`, `src/ui/`)*: 읽기 전용 스냅샷만 렌더링.
  2. **선언형 콘텐츠 & 사전 유효성 검증**:
     - 런타임 코드에 챕터별/보스별 if-else 분기를 하드코딩하지 않고, 선언형 패턴 데이터를 로더/검증기가 사전 검증하여 이상치(중복 ID, 역전, 중첩 창)를 사전 차단.
  3. **순수 판정과 부작용의 분리**:
     - `입력 + 현재 시각 + 불변 계획`을 순수 함수로 평가하여 판정 결과를 도출하고, 상태 변경(HP 차감, 보상 지급)은 정산기가 단일 진입점으로 처리.

    9. `테스트 계획`: Baseline Check → Red(실패) 확인 → 최소 구현 → Green(통과) → 전체 회귀 검증 사이클 명시
    10. `선행 카드 및 스테이지 게이트`: 실제 GitHub URL 링크 기반 의존성 연결
    11. `추적 및 중복 방지 정책`: SSOT 및 레거시 보호 지침 명시
  - **원격 동기화**: GitHub Issues [#502~#539](https://github.com/Choyounhwa/-dream-guardian/issues/502)의 38개 본문 전면 수정 및 `docs/15_BOSS_ASSAULT_WORK_CARDS.md` 원장 동기화 완료.

## 3. 핵심 의사결정 매트릭스 (Key Decisions Summary)

| 구분 | 결정 항목 | 결정된 정책 및 사양 | 비고 |
|---|---|---|---|
| **루프 철학** | 게임 진행 방식 | 정답/오답 화면 분기 폐지, 보스 공격 대응형 단일 흐름 통합 | 연속 타격감 및 플로우 유지 |
| **인지 시간** | 문제 생각 시간 | 문제 투척 연출 종료 및 선명 표시 시점부터 **최소 8박(BPM 100 기준 4.8초)** 보장 | 인지 과부하 방지 |
| **복합 운동** | 상·하체 피트니스 | **답 펀치 ↔ 스쿼트 회피 1:1 교대** (펀치 4박, 스쿼트 4박) | 전신 피트니스 정체성 보존 |
| **공격/판정** | 답안 탄환 처리 | 1쌍 2개 탄환을 단일 공격(pairId)으로 취급. 정답 시 쌍 전체 무효화, 오답 시 도착 시점 1회 피격 | 인과율 및 피격감 명확화 |
| **모션 안전** | 연속 펀치 및 스쿼트 | 펀치 손 회수(re-arm) 판정 필수, 스쿼트 직립 복귀 확인 필수 | 판정 씹힘 및 날먹 방지 |
| **아키텍처** | 레거시 공존 | 세션 단위 모드 분리 (`legacy` vs `boss_assault`), 배타적 실행 보장 | 기존 기능 무충돌 보존 |
| **자원 관리** | 체력/마나 소유권 | 기존 `BattleState`(플레이어 HP), `BossController`(보스 HP) 인스턴스 단일 권위 유지 | 데이터 분산 및 불일치 차단 |
| **설계 원칙** | 데이터와 로직 분리 | `types`(계약) / `config`(수치) / `data`(패턴 콘텐츠) / `game`(로직) / `render`(화면)의 엄격한 물리적 분리 | 유지보수성 및 확장성 극대화 |
| **카드 관리** | 작업 규격 | 단일 파일 변경 한도(src/config <= 3개) 준수, **#470 표준 포맷 전면 적용** | 안전한 점진적 TDD 보장 |
