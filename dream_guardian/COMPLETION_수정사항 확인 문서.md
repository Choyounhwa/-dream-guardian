# 꿈의 수호신 - 작업 완료 정리

작성일: 2026-09-20

## 게임 핵심 루프

1. 플레이어가 제자리 달리기로 다음 사고의 빛(문제)에 접근한다.
2. 수학 문제는 화면의 텍스트 패널에 표시되고, Web Speech API가 문제를 한국어로 읽는다.
3. 최초 2초 동안 문제를 확인한다. 이후 중앙에서 0.6초 준비 자세를 만든다.    ----------------------- 준비자세 삭제 
4. 화면 중하단의 두 활성 구역 중 답을 고른다. 선택지는 색상으로 어떤 신체를 움직여야 하는지 알려준다.
5. 같은 색의 신체 표식을 해당 구역으로 옮겨 0.8초 유지하면 답을 선택한다.
6. 정답 하나는 수호신 마나 25를 전달한다. 마나 100에서 수호신이 `사고의 별`을 시전해 보스에게 피해 4를 준다.
7. 오답은 수호신 HP에 피해를 주지만, 이전에 모은 마나는 보존한다.
8. 보스 HP를 모두 소진하면 다음 장 해금/결과 화면으로 이동한다. 5장 나이트메어는 엔딩으로 전환한다.    ----------------------------- 종료시 결과화면을 팝업으로 띄우고 몇초후 운동 기록 화면으로 이동

## 답안 입력 설계

> 최신 구현은 12구역 포즈 레시피가 아니라 `answer-selection.js`의 **색상 스켈레톤 커서 / 10구역 답안 시스템**이다. 상세 문서: `ANSWER_SELECTION_DESIGN.md`.  ------ 10구역은 답안이 아닌 정답을 선택하기 위한 피트니스 피봇영역에 가깝다.

- 조작판 커서는 요구된 신체 부위마다 하나만 표시한다. 같은 부위가 양쪽 답안에 반복되더라도 커서는 복제되지 않는다. ------------------------- 커서는 상시표시로 변경 (색상이 눈에 띄어야함)

- 구현 파일: `zone-input.js`
- 상세 명세: `POSE_DESIGN.md`
- 화면 중앙은 중립/준비 구역이고 답이 없다.
- 활성 답은 12구역 중 서로 다른 2곳만 사용한다. 모든 구역은 반열린 사각형으로 정의되어 서로 겹치지 않는다.      
- 색상과 형태:
  - 손: 시안 원 + 약한 동심 링    ----------------------------- 손바닥 포인트에 위치 
  - 얼굴: 노랑 타원, 투명도 50%    ----------------------- size를 얼굴의 크기에 맞추고 색상은 수호신과 같은 색상으로
  - 어깨: 보라 사각형           -------------------  꼭지점 라운드된 부드러운 사각형
  - 골반: 주황 역삼각형		------------------ 꼭지점 라운드된 부드러운 역 삼각형 (카메라에서 입력된 골반의 사이즈보다 약간 더 크게)
- 스켈레톤 선은 10% 투명도, 주요 신체 표식은 100% 불투명도다. 관절 원은 기존보다 1.5배 크기이며 머리/목 위치도 표시한다. 		----------- 신체표식은 손목링과 같은 효과를 주어 전체 분위기의 통일성이 필요하다
- 한 손, 양손, 교차 손, 양어깨, 골반, 얼굴을 사용하는 12개 레시피가 순환한다.             ------------- 어깨는 둘중 한쪽만으로도 답을 선택할수 있다. 
- 다른 신체 표식이나 손만 이동해서는 해당 답을 충전할 수 없다. 양손/양어깨 레시피는 두 표식 모두, 교차 레시피는 실제 손 좌우 순서 반전까지 요구한다.	------------------  정답(correct)에서 요구하는 신체표식을 모두 만족해야함 ㄴ답을 충전할수 있다.  

## 화면·HUD

- 상단: 수호신의 푸른 달 문양 에너지 바와 몬스터의 붉은 문양 에너지 바. 중앙 `VS` 표시는 제거했다. 숫자는 각 바 내부에 표시한다.
- 상단 카메라: 16:9 비율로 고정해 위쪽에 배치한다. 남은 하단 공간은 답 구역·수호신·UI 전용이다.
- 배경: 빨간 와이어 그리드에서 달리기 시 주황, 75% 이상 피버에서 파랑으로 보간 전환한다. 천장/바닥 원근 그리드와 중앙 검은 공간은 제공된 첫 이미지의 구도를 반영한다.	------- 가로세로 그리드가 겹쳐서 생긴 사각형들이 정사각으로 보이도록 세로그리드의 폭을 조절한다,   소실점은 보스에게로 1개 설정하고 원근감을 느낄수 있도록 심도조절해줘  
- 달리기 진행도: 수호신을 가리지 않도록 수호신 아래의 가로 게이지로 렌더링한다.
- 직접 조작 바: 플레이 중 하단에 `홈으로`, 중앙 HUD, `멈추기`를 표시한다. 이 버튼들은 HTML 직접 클릭/터치에서만 동작한다.    
- 멈추기: 게임 타이머, 모션 갱신, 진행을 멈추고 `계속하기`, `기록 보기`, `메뉴 보기`, `홈으로 가기`를 보여준다.   		------  메뉴 손 커서로 두손모아 선택할수 있도록 변경 
- 이미지 레퍼런스 적용: 대화에 첨부된 UI 시트는 로컬 이미지 파일로 제공되지 않아 실제 픽셀 크롭은 할 수 없었다. 대신 은하 보라색 그라데이션, 진주광 내부 테두리, 둥근 크리스털 테두리, 달 문양 에너지 아이콘 형태를 CSS/캔버스로 재현했다.

## 음성·문제 표시

- 문제 팝업에는 문제 텍스트만 표시한다. `문제 다시 듣기`, `음성 켜짐` 버튼과 확대 읽기 팝업을 제거했다.
- 음성은 비차단 보조 안내다. 음성 종료 이벤트를 기다리지 않으며, 종료/오류 이벤트가 누락돼도 게임이 멈추지 않는다.
- 음성이 3초 안에 시작하지 않으면 해당 음성만 취소하고 게임을 계속한다. 음성 전체 최대 시간도 안전 타이머로 제한한다.
- 문제 텍스트는 HTML 텍스트 영역의 줄바꿈/스크롤을 사용한다. 길이가 긴 문항도 한 줄 캔버스 텍스트로 잘리지 않는다.

## 카메라·플랫폼

- 기본 카메라는 페이지 시작 시 자동 요청한다. 전후면 선택/카메라 시작/터치 연습 모드 UI는 제거했다.
- 카메라 실패 시에도 PC 키보드/클릭으로 테스트할 수 있다.
- iPhone 웹캠은 HTTPS 또는 localhost 문맥에서만 동작한다. 이 프로젝트의 로컬 HTTP 서버는 PC 테스트용이다.
- 실제 카메라 자세 정확도와 모바일 음성은 기기/거리/조명에 따라 다르므로 다음 단계에서 실기기 값으로 `zone-input.js`의 `PARTS.gain`, `SETTINGS`, `POSES`를 조정한다.

## 최신 안정화 수정

- 메뉴는 전신/하반신이 아닌 **어깨 + 두 손목**만으로 기존 손 커서를 계산한다. 메뉴 카메라 화면에서도 **두 손을 어깨 너비의 80% 이내로 모은 뒤** 0.8초 버튼 위에 유지하면 선택한다. 메뉴 손 커서는 메뉴를 모두 그린 뒤 마지막 전면 레이어에서 렌더링된다.
- 메뉴 커서는 두 기존 손 표식의 정확한 중점에 하나만 생성된다. 두 손의 거리가 기준보다 멀어지거나 둘 중 하나의 인식 신뢰도가 낮아지면 즉시 사라진다.
- `gameLoop()`은 다음 프레임을 먼저 예약하고, 업데이트/렌더링 전체를 오류 격리한다. 문제 출제·음성·캔버스 렌더링에서 예외가 발생해도 프레임 루프 자체는 멈추지 않고 상태 문구로 오류 횟수를 표시한다.
- 문제 음성 호출은 렌더 스택 바깥의 타이머로 지연 실행한다. Safari/브라우저가 자동 음성을 거부해도 음성만 취소되며 질문 패널, 타이머, 12구역 입력은 계속 갱신된다.
- `runtime.test.cjs`는 다리 랜드마크 없이 손 체류로 첫 메뉴 챕터가 선택되는지, 신뢰도 낮은 손은 선택되지 않는지까지 검증한다. `menu-input.test.cjs`는 메뉴 커서 거울 방향과 버튼 히트 영역을 검증한다.

## 최근 메뉴/프레임 복구

- 메뉴용 커서를 별도로 추가하지 않고, 기존 손 커서를 **하나만** 유지한다. 오른쪽 손목 우선, 추적 유실 시 왼쪽 손목 보조 전환이다.
- 메뉴 버튼과 메뉴 손 커서는 같은 화면 좌표를 사용한다. 메뉴 카드를 모두 그린 뒤 손 커서를 마지막으로 렌더링하므로 메뉴 뒤로 가려지지 않는다.
- 메뉴 체류 판정은 하반신을 요구하지 않는다. 어깨 + 선택 손목만 신뢰도 0.5 이상이면 작동하며 0.8초 체류한다.
- 문제 출제 직후에는 다음 애니메이션 프레임을 먼저 예약하고, 상태 갱신/음성 호출/렌더링을 예외 격리한다. 프레임 하나가 실패해도 다음 프레임은 계속 실행한다. 음성은 렌더 스택 밖의 지연 작업으로 호출한다.

## PC 테스트 조작

- `Space`: 준비 통과 또는 달리기 진행도 충전
- `1`, `2`: 문제의 첫/둘째 활성 답 선택
- 활성 답 구역 직접 클릭: 해당 답 선택
- `멈추기`/`홈으로`/휴식 메뉴: 마우스 직접 클릭

## 테스트

다음 명령을 모두 통과했다.

```powershell
node dream_guardian/zone-input.test.cjs
node dream_guardian/runtime.test.cjs
node dream_guardian/question-speech.test.cjs
```

- `zone-input.test.cjs`: 12구역 비중첩, 경계 소유, 12레시피의 양방향 도달, 양손/교차/잘못된 부위/동시 입력/추적 유실 검증
- `runtime.test.cjs`: 달리기 완료 전환, 단일 출제, 음성 중 입력, 답 구역 클릭, 마나 전투, 카메라 변환 검증
- `question-speech.test.cjs`: 한국어 수식 변환, 종료/오류/취소/시작 지연/미지원 환경 안전 처리 검증
