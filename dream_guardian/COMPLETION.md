# 꿈의 수호신 - 작업 완료 정리

작성일: 2026-09-20

## 게임 핵심 루프

1. 플레이어가 제자리 달리기로 다음 사고의 빛(문제)에 접근한다.
2. 수학 문제는 화면의 텍스트 패널에 표시되고, Web Speech API가 문제를 한국어로 읽는다.
3. 최초 2초 동안 문제를 확인한다. 이후 첫 유효 프레임을 중립 기준 자세로 사용한다.
4. 화면의 활성 피트니스존 또는 답안 원에서 답을 고른다. 선택지는 색상으로 어떤 신체를 움직여야 하는지 알려준다.
5. 같은 색의 신체 표식을 유효한 활성 존으로 옮겨 1초 유지하면 답을 선택한다.
6. 정답 하나는 수호신 마나 25를 전달한다. 마나 100에서 수호신이 `사고의 별`을 시전해 보스에게 피해 4를 준다.
7. 오답은 수호신 HP에 피해를 주지만, 이전에 모은 마나는 보존한다.
8. 보스 HP를 모두 소진하면 다음 장 해금/결과 화면으로 이동한다. 5장 나이트메어는 엔딩으로 전환한다.

## 답안 입력 설계

> 최신 구현은 12구역 포즈 레시피가 아니라 `answer-selection.js`의 **색상 스켈레톤 커서 / 10구역 답안 시스템**이다. 상세 문서: `ANSWER_SELECTION_DESIGN.md`.

- 조작판 커서는 요구된 신체 부위마다 하나만 표시한다. 같은 부위가 양쪽 답안에 반복되더라도 커서는 복제되지 않는다.

- 구현 파일: `answer-selection.js`
- 상세 명세: `ANSWER_SELECTION_DESIGN.md`
- 화면 중앙은 중립/준비 구역이고 답이 없다.
- 활성 답은 10개 피트니스존 중 호환되는 공용 존 집합을 사용한다. 모든 구역은 반열린 사각형으로 정의되어 서로 겹치지 않는다.
- 색상과 형태:
  - 손: 시안 원 + 약한 동심 링
  - 얼굴: 노랑 타원, 투명도 50%
  - 어깨: 보라 사각형
  - 골반: 주황 역삼각형
- 스켈레톤 선은 10% 투명도, 주요 신체 표식은 100% 불투명도다. 관절 원은 기존보다 1.5배 크기이며 머리/목 위치도 표시한다.
- 한 손, 양손, 어깨, 골반 조합 레시피가 순환한다.
- 필요한 색상 커서가 각각 호환되는 활성 존에 모두 들어와야 충전한다.

## 화면·HUD

- 상단: 수호신의 푸른 달 문양 에너지 바와 몬스터의 붉은 문양 에너지 바. 중앙 `VS` 표시는 제거했다. 숫자는 각 바 내부에 표시한다.
- 상단 카메라: 16:9 비율로 고정해 위쪽에 배치한다. 남은 하단 공간은 답 구역·수호신·UI 전용이다.
- 배경: 빨간 와이어 그리드에서 달리기 시 주황, 75% 이상 피버에서 파랑으로 보간 전환한다. 천장/바닥 원근 그리드와 중앙 검은 공간은 제공된 첫 이미지의 구도를 반영한다.
- 달리기 진행도: 수호신을 가리지 않도록 수호신 아래의 가로 게이지로 렌더링한다.
- 직접 조작 바: 플레이 중 하단에 `홈으로`, 중앙 HUD, `멈추기`를 표시한다. 이 버튼들은 HTML 직접 클릭/터치에서만 동작한다.
- 멈추기: 게임 타이머, 모션 갱신, 진행을 멈추고 `계속하기`, `기록 보기`, `메뉴 보기`, `홈으로 가기`를 보여준다.
- 이미지 레퍼런스 적용: 대화에 첨부된 UI 시트는 로컬 이미지 파일로 제공되지 않아 실제 픽셀 크롭은 할 수 없었다. 대신 은하 보라색 그라데이션, 진주광 내부 테두리, 둥근 크리스털 테두리, 달 문양 에너지 아이콘 형태를 CSS/캔버스로 재현했다.

## 음성·문제 표시

- 문제 팝업에는 문제 텍스트만 표시한다. `문제 다시 듣기`, `음성 켜짐` 버튼과 확대 읽기 팝업을 제거했다.
- 음성은 비차단 보조 안내다. 음성 종료 이벤트를 기다리지 않으며, 종료/오류 이벤트가 누락돼도 게임이 멈추지 않는다.
- 음성이 3초 안에 시작하지 않으면 해당 음성만 취소하고 게임을 계속한다. 음성 전체 최대 시간도 안전 타이머로 제한한다.
- 문제 텍스트는 HTML 텍스트 영역의 줄바꿈/스크롤을 사용한다. 길이가 긴 문항도 한 줄 캔버스 텍스트로 잘리지 않는다.

## 카메라·플랫폼

- 기본 카메라는 페이지 시작 시 자동 요청한다. 전후면 선택/카메라 시작/터치 연습 모드 UI는 제거했다.
- 카메라 실패 시에도 PC 키보드/클릭으로 테스트할 수 있다.
- iPhone 웹캠은 HTTPS 또는 localhost 문맥에서만 동작한다. 이 프로젝트의 로컬 HTTP 서버는 PC 테스트용이다.
- 실제 카메라 자세 정확도와 모바일 음성은 기기/거리/조명에 따라 다르므로 다음 단계에서 실기기 값으로 `answer-selection.js`의 커서 이득과 존 좌표를 조정한다.

## 최신 안정화 수정

- 메뉴는 전신/하반신이 아닌 **어깨 + 두 손목**만으로 기존 손 커서를 계산한다. 메뉴 카메라 화면에서도 **두 손을 어깨 너비의 80% 이내로 모은 뒤** 0.8초 버튼 위에 유지하면 선택한다. 메뉴 손 커서는 메뉴를 모두 그린 뒤 마지막 전면 레이어에서 렌더링된다.
- 메뉴 커서는 두 기존 손 표식의 정확한 중점에 하나만 생성된다. 두 손의 거리가 기준보다 멀어지거나 둘 중 하나의 인식 신뢰도가 낮아지면 즉시 사라진다.
- `gameLoop()`은 다음 프레임을 먼저 예약하고, 업데이트/렌더링 전체를 오류 격리한다. 문제 출제·음성·캔버스 렌더링에서 예외가 발생해도 프레임 루프 자체는 멈추지 않고 상태 문구로 오류 횟수를 표시한다.
- 문제 음성 호출은 렌더 스택 바깥의 타이머로 지연 실행한다. Safari/브라우저가 자동 음성을 거부해도 음성만 취소되며 질문 패널, 타이머, 12구역 입력은 계속 갱신된다.
- `runtime.test.cjs`는 다리 랜드마크 없이 손 체류로 첫 메뉴 챕터가 선택되는지, 신뢰도 낮은 손은 선택되지 않는지까지 검증한다. `menu-input.test.cjs`는 메뉴 커서 거울 방향과 버튼 히트 영역을 검증한다.

## 수정사항 확인 문서 반영

- `POSE_DESIGN_수정사항 확인 문서.md`, `COMPLETION_수정사항 확인 문서.md`의 코멘트를 검토했다. 최신 답안 입력은 피트니스존 기반 10구역이며, 준비 자세를 별도 강제하지 않는다.
- 손 입력은 MediaPipe Hands의 손바닥 중앙(랜드마크 9)을 우선 사용하고, 손 인식이 없을 때만 Pose 손목을 보조점으로 사용한다.
- 각 스켈레톤 커서는 상시 영상에 표시되며 손=시안/노랑, 얼굴=수호신 계열 아이스블루 50% 타원, 어깨=보라 라운드 사각형, 골반=주황 라운드 역삼각형이다. 제어판에는 현재 문제에서 요구되는 색만 1개씩 표시한다.
- 피트니스존 선택 화면에서는 같은 부위를 실제 영상과 조작판에 동시에 색상 커서로 그리지 않는다. 영상은 중립 스켈레톤선만, 조작판은 요구 부위별 단일 색상 커서만 보여 중복 커서를 제거한다.
- 골반 다이아몬드는 이전 2배 패스 기준에서 전체 폭 70%, 높이는 그 높이의 50%로 축소한 납작한 다이아몬드다. 골반만 기존 강한 Breathing 값(주기 170ms, 범위 22%)을 사용한다. Expanding/Blow 불투명도는 직전 값의 50%로 낮췄다. Trail은 단일 추정 위치가 아니라 최근 실제 좌표 3개를 보관해 커서 형태 그대로 렌더링한다.
- 피트니스존 경계에서도 충전하되, 중심에 가까울수록 1.5배/경계는 0.75배 속도로 충전한다. 여러 요구 커서가 한 피트니스존에 배정될 수 있고 그 경우 모두 들어와야 충전한다.
- 일반 보스 종료 시 결과 팝업을 3초 노출한 뒤 운동 기록 모달을 연다.
- `FITNESS_ZONE_CATALOG.md`, `FITNESS_ZONE_EDITOR.md`를 추가해 국민체조 기반 존/조합을 문서로 편집할 수 있게 했다.

## 최근 메뉴/프레임 복구

- 메뉴용 커서를 별도로 추가하지 않고, 기존 손 커서를 **하나만** 유지한다. 오른쪽 손목 우선, 추적 유실 시 왼쪽 손목 보조 전환이다.
- 메뉴 버튼과 메뉴 손 커서는 같은 화면 좌표를 사용한다. 메뉴 카드를 모두 그린 뒤 손 커서를 마지막으로 렌더링하므로 메뉴 뒤로 가려지지 않는다.
- 메뉴 체류 판정은 하반신을 요구하지 않는다. 어깨 + 선택 손목만 신뢰도 0.5 이상이면 작동하며 0.8초 체류한다.
- 문제 출제 직후에는 다음 애니메이션 프레임을 먼저 예약하고, 상태 갱신/음성 호출/렌더링을 예외 격리한다. 프레임 하나가 실패해도 다음 프레임은 계속 실행한다. 음성은 렌더 스택 밖의 지연 작업으로 호출한다.

## 최신 카메라 인식 복구

- Pose 라이브러리와 Hands 라이브러리를 별도 파이프라인으로 초기화한다. Hands 오류가 Pose 스켈레톤을 중단시키지 않는다.
- Pose 결과의 `visibility` 누락값은 유효한 랜드마크로 정규화한다. 단일 빈 Pose 프레임은 스켈레톤을 지우지 않으며, 12회 연속 빈 프레임과 1.5초 무검출 뒤에만 추적을 초기화한다.
- 카메라 `loadedmetadata`와 `play()`를 확인한 뒤 프레임을 전송한다. Pose/Hands 전송은 각각 30fps 이하로 제한해 저성능 기기의 동시 전송 과부하를 줄인다.
- 카메라 상태 문구는 라이브러리 미로딩, 카메라 미연결, 영상 프레임 대기, 사람 미검출, 일시 추적 유실을 구분해 표시한다.
- 손 답안 입력은 Hands 손바닥 중앙을 우선 사용하되, Hands가 아직 인식하지 못한 경우 Pose 손목을 보조점으로 사용한다.

## PC 테스트 조작

- `Space`: 준비 통과 또는 달리기 진행도 충전
- `1`, `2`: 문제의 첫/둘째 활성 답 선택
- 답안 원 직접 클릭: 해당 답 선택
- 해당 답만 가능한 활성 피트니스존 직접 클릭: 해당 답 선택
- `멈추기`/`홈으로`/휴식 메뉴: 마우스 직접 클릭

## 테스트

다음 명령을 모두 통과했다.

```powershell
node dream_guardian/zone-input.test.cjs
node dream_guardian/answer-selection.test.cjs
node dream_guardian/menu-input.test.cjs
node dream_guardian/question-evaluator.test.cjs
node server.test.cjs
node dream_guardian/runtime.test.cjs
node dream_guardian/question-speech.test.cjs
```

- `answer-selection.test.cjs`: 최신 10존 선택지 계약, 호환 존, 커서 보정 검증
- `menu-input.test.cjs`: `visibility`와 화면 좌표 `vis` 신뢰도 계약을 검증
- `question-evaluator.test.cjs`: CSV 수식 허용 범위와 코드 실행 차단을 검증
- `server.test.cjs`: 정적 서버 경로 탈출 및 접두사 형제 경로 차단을 검증
- `runtime.test.cjs`: 달리기 완료 전환, 단일 출제, 음성 중 입력, 답안 클릭, 마나 전투, 보스 회피 공격, 카메라 변환 검증
- `question-speech.test.cjs`: 한국어 수식 변환, 종료/오류/취소/시작 지연/미지원 환경 안전 처리 검증
