# 색상 신체 이동 / 12구역 입력 설계

> 현재 구현은 아래 초기 12구역 설계를 **색상 커서 10구역 답안 시스템**으로 교체했습니다. 최신 상세 기준은 `ANSWER_SELECTION_DESIGN.md`를 우선합니다.

## 기본 흐름
달리기 → 문제/음성 → 최초 2초 준비 → 편한 자세로 0.6초 정렬 → 지정 색상의 신체를 답 방향으로 이동 → **0.8초 연속 유지** → 마나 +25.

음성은 보조 안내입니다. `onend`를 기다려 게임을 잠그지 않습니다. 다시 듣기도 게이지를 초기화하지 않습니다. 화면 확대 팝업은 없습니다.

## 색상·모양
|부위|색상|영상 위 표시|입력 방식|
|---|---|---|---|
|손|시안 `#28E6FF`|양 손목 원|한 손 / 양손 / 교차|
|얼굴|노랑 `#FFD35A`|코 중심 세로 타원|얼굴 중심 이동|
|어깨|보라 `#CD94FF`|양 어깨 원|양쪽 모두 같은 구역|
|골반|주황 `#FF8B64`|두 골반 간격에 맞춘 역삼각형|골반 중점 이동|

색상은 정답 여부가 아니라 **움직여야 하는 신체**를 뜻합니다. 두 답은 같은 신체/같은 색상으로 출제해 색으로 정답을 알 수 없게 합니다. 다른 색 부위는 해당 문제에 영향을 주지 않습니다. 원/타원/삼각형과 부위명도 함께 표시합니다. 연결선은 불투명도 10%, 주요 표식은 100%입니다.

## 12구역 해석과 배치
요청의 `좌상하, 우상하, 위좌우, 아래좌우, 상하좌우`를 **좌측 상/하, 우측 상/하, 위쪽 좌/우, 아래쪽 좌/우, 상/하/좌/우**로 해석했습니다.
화면의 문제/HP/하단 HUD를 제외한 조작판(너비 94%, 높이 44%, y=40%)을 다음처럼 나눕니다. 중앙은 선택되지 않는 준비 공간입니다.			---------------- 이 구역 이름을 피트니스존 이라고 용어를 정의할게

```
├─────────┬────┴──────────┴────┬─────────┤
│ 왼쪽 위 │                   │오른쪽 위│
├─────────┤      준비         ├─────────┤
│ 왼쪽    │      공간         │오른쪽   │								
├─────────┤                   ├─────────┤
│왼쪽 아래│                   │오른쪽아래│

```

정규화 좌표 `(x,y,w,h)`는 `zone-input.js`의 `ZONES`에 있습니다. 위/아래 띠 높이는 각각 1/4, 좌우 띠 폭은 1/4이며 가운데 높이 1/2를 3분할합니다. 위 왼쪽과 왼쪽 위는 서로 다른 공간입니다.

- 한 문제에는 12개 중 **서로 다른 두 구역**만 답으로 활성화됩니다. 나머지는 위치 안내선입니다.
- 모든 판정은 `[시작, 끝)` 반열린 범위라 경계를 공유해도 중복 소유하지 않습니다.
- 자세 입력은 경계에서 0.025만큼 안쪽에 들어와야 충전합니다. 구역 이동/이탈 즉시 충전 초기화.	---------------- 경계에 닿기만 해도 충전이 되지만 중심에 가까울수록 빨리 충전 되도록  변경
- 두 손이 서로 다른 답에 동시에 들어가면 어느 것도 확정하지 않습니다.		-------------------- 양손이 한 칸에 들어갈수도 있음 ex) 정답요구색상은 2개인대 피트니스존에 뜬 칸은 1개 일 경우 두개가 같이 들어가야지만 충전되어야함
- PC 테스트: `1`/`2` 키 또는 실제 활성 구역 클릭. 중앙이나 비활성 구역 클릭은 무효.

## 작은 움직임으로 화면 이탈 줄이기
영상 자체는 요청대로 전체 배경 cover를 유지합니다. 원본 카메라 좌표를 같은 비율로 변환해 신체 표시를 정렬합니다.

**영상의 실제 신체 표식**과 **조작판의 동일 색상 이동 표식**은 구분합니다. 준비 자세에서 관련 부위의 시작 위치를 저장하고 작은 변위를 조작판 중앙에서 확대합니다. 조작판에 보이는 표식 중심이 판정 좌표와 같습니다. 실제 손/골반을 화면 가장자리까지 옮길 필요가 없습니다.

```
판정 x = 0.5 + (현재 x - 준비 x) / (준비 몸통길이 × gainX × 2)
판정 y = 0.5 + (현재 y - 준비 y) / (준비 몸통길이 × gainY × 2)
```

`PARTS.gain` 값이 작을수록 적은 이동으로 선택할 수 있습니다. 손 `(0.65,0.85)`, 얼굴 `(0.22,0.25)`, 어깨 `(0.30,0.25)`, 골반 `(0.30,0.32)`. 각 레시피에 `gain:[x,y]`를 넣으면 개별 덮어쓰기 가능합니다. 초기값은 실측 최종값이 아니며 장치/거리별 조정이 필요합니다.

## 구현된 포즈 순환표
|ID|입력 조건|답 위치|행동 안내 / 의도|
|---|---|---|---|
|one-diagonal|한 손|좌상/우상|한 팔을 작게 대각선으로 뻗기; 어깨 가동|
|one-side|한 손|좌/우|옆으로 뻗고 유지; 가슴·옆구리 열기|
|both-high|양손 모두|위좌/위우|양손을 같은 대각선으로 올리기; 양팔 스트레칭|
|both-low|양손 모두|아래좌/아래우|두 손을 같은 아래 방향으로 밀기|
|cross|양손 X 교차 + 중점|상/하|가슴 앞에서 교차한 채 살짝 올리기/내리기|
|shoulder-side|양어깨 모두|좌/우|발은 제자리에서 몸통 이동|
|shoulder-diagonal|양어깨 모두|좌상/우상|작은 체중 이동 + 양어깨 올리기|
|shoulder-down|양어깨 모두|좌하/우하|무릎을 조금 굽히며 몸통 이동|
|hip-side|골반 중점|좌/우|골반 중심의 좌우 체중 이동|
|hip-vertical|골반 중점|상/하|위: 뒤꿈치 살짝 들기, 아래: 미니 스쿼트|
|hip-diagonal|골반 중점|아래좌/아래우|작게 앉으며 체중 이동|
|face-side|얼굴 중심|좌/우|목을 꺾기보다 몸통과 얼굴을 함께 조금 이동|

크로스는 손목 좌우 순서가 준비 자세와 뒤집히고 간격이 몸통길이의 12% 이상이어야 합니다. 교차 없이 두 손의 평균만 이동하는 우회는 차단합니다. 손 한 개 레시피는 같은 답에 정확히 한 손만 들어와야 하며 양손 레시피는 두 표식이 같은 답 구역 안에 있어야 합니다.

이 판정은 **방향 이동과 유지**를 확인합니다. 어깨 하강이 반드시 무릎 굽힘인지, 골반 상승이 반드시 뒤꿈치 들기인지까지 생체역학적으로 검증하지는 않습니다. 깊은 런지·큰 점프를 필수로 요구하지 않습니다. 유산소 리듬은 문제 사이 달리기, 가동·스트레칭 동작은 답 선택으로 구성합니다. 운동 효과는 설계 의도이며 측정 결과가 아닙니다.

## 수정 위치
- 색상/형태/민감도: `PARTS`
- 구역 이름/좌표: `ZONES` (겹침 테스트 필수)
- 순환 순서/추가 포즈: `POSES` 배열; `zones`는 반드시 다른 두 ID
- 유지/준비/신뢰도/허용 프레임 간격: `SETTINGS`
- 표시판 위치: `board(width,height)` — 그리기와 클릭 모두 동일 함수 사용
- 실제 스켈레톤: `index.html`의 `drawPoseSkeleton`, `drawPartMarker`
- 음성 안내: `question-speech.js`, 게임 콜백은 UI 상태만 갱신하며 입력과 분리

다음 후보: 한 어깨 번갈아 올리기(`one` shoulder variant), 손목 교차 좌우 풀기, 골반 2단계 좌→중앙→우. 순서 동작은 현재 단일 유지 판정에 억지로 넣지 말고 레시피에 단계 상태를 추가하는 방식으로 확장합니다.
